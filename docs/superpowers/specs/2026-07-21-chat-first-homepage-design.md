# Chat-first 博客首页设计规格

## 1. 背景与目标

现有博客基于 VuePress 1，线上地址为 `https://blog.april-tong.cn/`。新版博客将使用 Nuxt 与 Nuxt Content 重构，并通过 API 接入现有 KnowFlow AI 知识库后端。

本阶段只实现新版首页布局。首页从传统文章聚合页调整为 AI 知识库入口，以聊天作为唯一主体，突出个人知识库的差异化体验。

## 2. 已确认的设计决策

- 视觉方向采用「深空知识站」：深蓝黑渐变背景、微弱网格、玻璃面板、胶囊导航与青紫极光点缀。
- 根路径 `/` 为全屏 AI 知识库聊天首页。
- `/chat` 后续通过 301 重定向到 `/`，不维护重复页面。
- 首页采用 Chat-only 结构，不展示最新文章卡片或其他内容区块。
- 文章、时间轴和关于页面通过顶部导航进入。
- 首页允许所有访客直接使用，不要求显式登录。
- AI 回答使用 SSE 流式输出。

## 3. 页面结构

### 3.1 全局背景

页面使用深蓝黑渐变背景，叠加低对比度网格和局部青紫色光晕。背景只用于营造空间感，不使用高频粒子、跟随鼠标动画或持续闪烁效果，避免干扰阅读和增加性能负担。

### 3.2 顶部导航

顶部使用半透明胶囊导航，包含以下入口：

- `april.dev` 品牌标识，点击返回首页。
- 「文章」，进入文章列表页。
- 「时间轴」，进入归档时间轴。
- 「关于」，进入个人介绍页。
- 「GitHub」，在新标签页打开个人 GitHub。

桌面端展示完整导航；移动端保留品牌标识和菜单按钮，次要入口收进抽屉菜单。

### 3.3 聊天主体

聊天主体使用单个大型玻璃面板，占据导航以下的主要可视区域。

初始状态包含：

- AI 光球标识。
- 主标题「今天想了解什么？」。
- 一句能力说明：回答来自 April 的技术笔记和知识文档，并提供引用来源。
- 3 个快捷问题，用真实问题示例降低首次使用门槛。
- 底部输入框和发送按钮。
- 简短提示「AI 可能会犯错，请核对引用来源」。

进入对话后：

- 欢迎内容收起，面板切换为消息列表。
- 用户消息与 AI 消息使用不同对齐方式和视觉层级。
- AI 消息支持 Markdown、代码块、复制和引用来源。
- 输入区固定在聊天面板底部，不随消息列表滚走。
- 生成期间发送按钮切换为「停止生成」。

## 4. 组件边界

首页按职责拆分为以下单元：

- `AppHeader`：品牌、桌面导航和移动端菜单。
- `KnowledgeChatShell`：聊天首页的布局与状态切换。
- `ChatWelcome`：欢迎文案、AI 标识和快捷问题。
- `ChatMessageList`：消息列表、自动滚动和空状态。
- `ChatMessage`：单条消息、Markdown、代码块与引用入口。
- `ChatComposer`：输入、发送、停止生成和键盘操作。
- `ChatStatusNotice`：网络中断、限流和后端异常提示。
- `useKnowledgeChat`：聊天状态与 API 适配接口。本阶段使用可替换的演示实现，不接入真实后端。

各组件通过明确的 Props 和事件通信，不直接读取全局 DOM，也不在展示组件内发起网络请求。

## 5. 状态与交互

首页需要覆盖以下状态：

1. **欢迎态：** 尚无消息，显示简介、快捷问题和输入框。
2. **用户已发送：** 立即追加用户消息，并显示 AI 生成占位状态。
3. **生成中：** 持续追加回答内容，允许停止生成。
4. **生成完成：** 展示完整回答、复制操作和引用来源入口。
5. **用户停止：** 保留已生成内容，并标记回答已停止。
6. **请求失败：** 在消息区域展示错误原因和「重新发送」操作。
7. **触发限流：** 说明需要稍后重试，不暴露服务端内部信息。

快捷问题点击后直接填入并发送。桌面端按 `Enter` 发送、`Shift + Enter` 换行；移动端只通过发送按钮提交，避免输入法误触。

## 6. 数据流与后续接口

真实接口接入阶段采用以下链路：

1. Nuxt Server API 自动为访客申请匿名令牌。
2. 匿名令牌保存在 `HttpOnly` Cookie 中，浏览器脚本不能直接读取。
3. 首页调用同源 Nuxt Server API，由服务端代理 KnowFlow AI。
4. Nuxt Server API 转发 SSE，并保持 `start`、`delta`、`done` 和 `error` 事件语义。
5. 前端使用 `AbortController` 停止当前生成请求。

KnowFlow AI 当前聊天控制器受 `JwtAuthGuard` 保护。后续需要增加匿名访客令牌能力，不能在浏览器中共享固定账号或长期密钥。

## 7. 响应式与无障碍

- 桌面端聊天面板限制最大宽度，宽屏下保持内容集中。
- 移动端减少外边距和圆角，聊天面板使用完整可用高度。
- 输入区考虑安全区域 `env(safe-area-inset-bottom)`。
- 所有交互控件支持键盘焦点，并提供可见的焦点样式。
- 图标按钮提供可访问名称。
- 动效遵循 `prefers-reduced-motion`，用户选择减少动态效果时关闭光晕漂移和过渡位移。
- 文字与背景对比度满足 WCAG AA 的常规文本要求。

## 8. SEO

虽然首页不展示文章列表，仍配置以下信息：

- 唯一的页面标题和描述。
- Canonical URL 指向 `/`。
- Open Graph 与社交分享元数据。
- 指向文章列表页的可抓取导航链接。
- 描述站点和作者信息的结构化数据。

文章内容的搜索入口由后续文章列表页、详情页、站点地图和 RSS 提供。

## 9. 本阶段范围

### 9.1 包含

- 初始化 Nuxt 与 Nuxt Content 工程。
- 实现深空科技风全屏 Chat 首页。
- 实现欢迎态、演示消息态、生成态和异常态。
- 实现桌面端与移动端响应式布局。
- 建立可替换的聊天 API 适配层。
- 配置首页 SEO、基础无障碍和深色主题。
- 完成类型检查、组件测试、生产构建和浏览器视觉验收。

### 9.2 不包含

- 旧 Markdown 文章迁移。
- 文章列表、文章详情、时间轴和关于页面的正式实现。
- 旧 URL 的 301 映射。
- KnowFlow AI 匿名令牌后端改造。
- 真实 SSE 接口接入和会话持久化。
- 评论、搜索、站点地图和 RSS。

## 10. 验收标准

- 访问 `/` 时直接看到纯聊天首页，不出现文章卡片或传统博客 Hero。
- 页面视觉与已确认的「深空知识站」方案一致。
- 快捷问题、输入、发送、停止生成和重试均有完整 UI 反馈。
- 桌面端和常见移动端宽度下无横向滚动、遮挡或不可操作控件。
- 键盘可以完成导航、输入和发送操作。
- 页面在减少动态效果模式下仍可正常使用。
- Nuxt 类型检查、测试和生产构建全部通过。
- 浏览器中完成桌面端和移动端视觉检查，没有明显布局问题。

## 11. 后续阶段

首页完成后，建议按以下顺序继续：

1. 迁移旧 Markdown，并实现文章列表与详情页。
2. 建立旧 URL 到新路由的 301 映射。
3. 为 KnowFlow AI 增加匿名访客令牌和限流。
4. 接入真实 SSE、引用来源与匿名会话。
5. 实现时间轴、关于、搜索、站点地图和 RSS。
