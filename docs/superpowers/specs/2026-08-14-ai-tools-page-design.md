# AI 工具页设计规格

## 1. 背景与目标

博客当前通过顶部导航提供 Chat、文章、关于和 GitHub 入口，但缺少集中整理 AI 开发工具的页面。本阶段新增「AI 工具」一级导航，将常用 Skills 与模型上下文协议（Model Context Protocol，MCP）工具放在同一个内容入口中。

页面承担两层职责：

- 列表页帮助访客快速理解工具的用途，并按 Skills 或 MCP 筛选。
- 详情页提供可复制的安装命令、配置示例和基础用法，帮助访客完成安装与首次使用。

本阶段不提供在线安装、账号授权或远程执行能力。所有复制内容只进入用户剪贴板，由用户自行确认并在本地执行。

## 2. 已确认的设计决策

- 顶部导航只增加一个「AI 工具」入口，不把 Skills 和 MCP 拆成两个一级入口。
- 列表页默认混合展示全部工具，提供「全部」「Skills」「MCP」筛选。
- 每个工具拥有独立详情页，详情页提供作用、场景、安装、配置、用法和注意事项。
- 首版收录 8 个工具，包含 4 个 Skills 和 4 个 MCP。
- 首版沿用现有深色、青色高光和玻璃面板视觉体系，不引入新的图标库或远程图片依赖。
- 内容使用 Nuxt Content 管理，后续新增工具时不需要修改列表页组件。
- 不展示安装量、Star 数和版本号等容易过期的数据。

## 3. 信息架构与路由

新增以下路由：

| 路由 | 用途 |
| --- | --- |
| `/ai-tools` | AI 工具列表与类型筛选 |
| `/ai-tools/:slug` | 单个工具详情 |

顶部导航顺序调整为：

```text
Chat　文章　AI 工具　关于　GitHub ↗
```

访问 `/ai-tools` 或任意 `/ai-tools/:slug` 时，「AI 工具」保持选中状态。移动端继续使用现有菜单展开方式，新增入口不会改变菜单交互模型。

## 5. 内容模型

在 `content.config.ts` 中新增 `aiTools` 页面集合，内容文件存放在 `content/ai-tools/`。每个 Markdown 文件包含以下元数据：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | `string` | 工具名称 |
| `description` | `string` | 列表卡片和 SEO 使用的一句话说明 |
| `type` | `'skill' \| 'mcp'` | 工具类型 |
| `order` | `number` | 稳定的展示顺序 |
| `platforms` | `string[]` | 已在正文中提供安装说明的平台 |
| `tags` | `string[]` | 用途标签，例如「前端设计」「浏览器调试」 |
| `officialUrl` | `string` | 官方文档或项目主页 |
| `repositoryUrl` | `string?` | 可选的源码仓库地址 |
| `featured` | `boolean` | 是否显示「推荐」标记 |
| `draft` | `boolean` | 草稿不进入列表，也不能公开访问 |

Slug 由文件名和 Content 路径生成，不在 Front Matter 中重复维护。`type` 的中文或英文展示名称由界面统一映射，避免内容中出现不一致写法。

每篇正文使用相同章节顺序：

1. 工具是什么
2. 适合哪些场景
3. 安装方式
4. 配置示例
5. 使用示例
6. 注意事项
7. 官方链接

安装和配置必须标明适用平台。首版优先提供 Codex 示例；只有经官方资料确认后，才补充 Claude Code、Cursor 或其他客户端示例。

## 6. 列表页设计

### 6.1 页面头部

页面头部使用紧凑 Hero，而不是首页式大面积宣传区。内容包括：

- 眉题「APRIL / AI TOOLBOX」。
- 标题「常用 AI 工具」。
- 简介「整理我常用和推荐的 Skills 与 MCP，包含安装、配置和使用示例。」
- 当前收录数量，以及 Skills 与 MCP 的数量摘要。

数量从内容集合计算，不在模板中硬编码。

### 6.2 类型筛选

Hero 下方显示「全部」「Skills」「MCP」三个胶囊按钮。筛选状态写入 URL：

```text
/ai-tools
/ai-tools?type=skill
/ai-tools?type=mcp
```

无效、重复或数组形式的 `type` 查询参数统一归一化为「全部」，并通过 `router.replace` 清理 URL。按钮使用 `aria-pressed` 表示状态，筛选后将结果数量通过可访问状态区域告知读屏软件。

### 6.3 工具卡片

列表采用响应式卡片网格：宽屏 3 列、中等宽度 2 列、移动端 1 列。每张卡片包含：

- 工具名称。
- `Skill` 或 `MCP` 类型徽标。
- 可选的「推荐」徽标。
- 一句话用途说明。
- 最多 3 个用途标签。
- 支持平台摘要。
- 「查看详情」链接。

卡片整体不嵌套多个重复链接，只保留一个清晰的详情入口。Hover 只提供轻微边框和位移反馈；减少动态效果模式下关闭位移。

筛选结果为空时展示说明和「查看全部」按钮。虽然首发内容不会触发空状态，但组件需要覆盖后续草稿或内容调整场景。

## 7. 详情页设计

详情页沿用文章阅读页的集中阅读结构，但不直接复用「文章」语义和样式类名。

页面包括：

- 返回 AI 工具列表的链接。
- 工具类型、标题、简介、平台和用途标签。
- Markdown 正文。
- 右侧信息面板，包含官方文档、源码仓库和正文目录。
- 同类型工具推荐，最多展示 3 个，排除当前工具。

工具不存在或处于草稿状态时返回 HTTP 404，错误消息为「AI 工具不存在」。

详情页不把工具配置声明为永远有效。安装区顶部增加短提示：执行前先查看官方链接，确认客户端版本、权限范围和最新配置格式。

## 8. 代码复制交互

Nuxt Content 的代码块通过自定义 `ProsePre` 组件增强。每个块右上角显示「复制」按钮，并遵循以下状态：

1. 默认显示「复制」。
2. 成功后显示「已复制」，约 2 秒后恢复。
3. 失败后显示「复制失败」，同时保留可手动选择的原始代码。

优先使用 `navigator.clipboard.writeText`。浏览器不支持 Clipboard API 或页面不处于安全上下文时，使用临时 `textarea` 作为兼容回退。复制按钮不能遮挡横向滚动条或代码内容。

复制状态使用 `aria-live="polite"` 通知辅助技术。代码块仍支持键盘选中和横向滚动，不依赖复制按钮才能使用。

## 9. 组件与职责边界

- `AppHeader`：新增导航入口及其活动状态判断。
- `AiToolHero`：列表页标题、简介与内容数量。
- `AiToolFilters`：类型筛选按钮和筛选事件。
- `AiToolList`：卡片网格和空状态。
- `AiToolCard`：单个工具摘要，不读取路由或内容集合。
- `AiToolSidebar`：详情页官方链接、源码链接和正文目录。
- `ProsePre`：代码展示与复制反馈。
- `useAiToolFilters`：筛选状态、URL 归一化和结果计算。
- `app/types/ai-tool.ts`：列表和组件使用的稳定类型。

页面负责查询 Nuxt Content、处理 404 和配置 SEO；展示组件不直接发起内容查询。

## 10. 数据流与异常处理

### 10.1 列表页

1. 查询所有 `draft = false` 的 `aiTools` 内容。
2. 按 `order`、`title` 稳定排序。
3. 将查询结果映射为轻量卡片数据。
4. 从路由查询参数初始化筛选状态。
5. 在用户切换类型时更新 URL 和过滤结果。

内容查询失败时交给 Nuxt 错误边界处理，不将错误伪装为空列表。

### 10.2 详情页

1. 按当前路径查询单个非草稿工具。
2. 未找到时抛出 404。
3. 同时查询同类型工具，用于相关推荐。
4. 使用当前内容生成 SEO 和结构化数据。

外部链接统一使用新标签页，并设置 `rel="noreferrer"`。正文中的命令只展示和复制，不自动执行。

## 11. SEO 与结构化数据

列表页配置独立标题、描述、Canonical URL 和 Open Graph 信息。详情页根据工具元数据生成：

- 页面标题：`<工具名称>｜AI 工具箱｜April 的技术笔记`。
- Canonical URL：当前工具的公开路径。
- Open Graph 标题和描述。
- `SoftwareApplication` JSON-LD，包含名称、描述、应用分类和官方 URL；不填写无法验证的价格、评分或版本。

所有 JSON-LD 内容继续使用项目现有的安全序列化方式，转义可能提前结束脚本标签的字符。

## 12. 响应式与无障碍

- 桌面端保持现有 1220 px 最大内容宽度。
- 960 px 以下详情页改为单列，侧栏进入正文之后。
- 720 px 以下卡片改为单列，页面边距和圆角与文章页保持一致。
- 所有按钮和链接具有至少 44 px 的可操作高度。
- 筛选按钮、复制按钮和移动菜单均支持键盘操作及可见焦点。
- 标签颜色不能成为区分 Skill 与 MCP 的唯一方式，始终显示文本。
- 文本与背景对比度满足 WCAG AA 常规文本要求。
- `prefers-reduced-motion: reduce` 下关闭非必要位移和过渡。

## 13. 测试策略

实现采用测试驱动开发，至少覆盖：

- `AppHeader` 展示「AI 工具」，并在列表和详情路由保持活动状态。
- 内容集合能够读取 8 个非草稿工具，Slug、类型、顺序和官方链接合法。
- 列表页默认展示全部工具，支持 Skill 与 MCP 筛选。
- 筛选状态与 `type` 查询参数双向同步，并清理无效参数。
- 工具卡片展示类型、简介、平台和详情链接。
- 详情页渲染正文、外部链接和同类型推荐。
- 未知或草稿工具返回 404。
- 代码复制成功、失败和兼容回退状态。
- SEO、Canonical URL 与 JSON-LD 不包含未转义内容。
- 桌面端和移动端浏览器视觉检查无横向溢出、遮挡或不可操作控件。

最终验证命令为：

```bash
pnpm test
pnpm typecheck
pnpm build
```

## 14. 本阶段范围

### 14.1 包含

- 顶部「AI 工具」导航入口。
- AI 工具列表页、类型筛选和空状态。
- 8 个首发工具的完整中文详情内容。
- 工具详情页、目录、官方链接和同类推荐。
- 安装命令与配置代码的一键复制。
- SEO、响应式、无障碍、测试和浏览器视觉验收。

### 14.2 不包含

- 在线执行安装命令。
- 代替访客完成 OAuth 或第三方账号授权。
- 工具评分、评论、收藏、搜索和排序。
- 自动抓取安装量、Star 数、版本号或官方文档变更。
- 第二批 Frontend Design、Web Design Guidelines、Playwright MCP 和 Sentry MCP 内容。
- 远程图片、第三方 Logo CDN 或新增图标依赖。

## 15. 验收标准

- 顶部导航在桌面端和移动端都能进入 `/ai-tools`。
- 列表页完整展示 8 个首发工具，并能按 Skills 和 MCP 筛选。
- 每个工具都能进入独立详情页，正文结构完整且官方链接可见。
- 所有安装命令和配置代码均可通过键盘访问的按钮复制。
- 复制失败时不丢失代码，也不阻止用户手动选择。
- 未知工具路径返回 404，草稿内容不公开。
- 页面沿用现有视觉体系，在常见桌面端和移动端宽度下无布局问题。
- 测试、类型检查和生产构建全部通过。
- 浏览器完成列表页、Skill 详情和 MCP 详情的桌面端与移动端视觉检查。
